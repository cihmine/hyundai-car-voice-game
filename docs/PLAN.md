# 1번 앱 개발 계획서 — 말게임
작성: 2026-10-31 · 내부 제출 목표: 2026-11-04
상태: 개발 지시용 계획. 구현·실차 검증이 완료됐다는 의미가 아니다.

## 1. 만들 경험
게임 선택, 답변, 설명 요청, 일시정지, 종료까지 말로 진행하는 차량용 게임이다. 어릴 때 아버지와 끝말잇기를 하며 고향에 내려가던 경험을 출발점으로 삼는다. 차량에서는 화면을 보지 않고 가볍게 참여할 수 있는 경험을 목표로 한다.

차별점은 범용 AI의 자유 대화보다 일관된 게임 규칙, 음성 인식 오류 복구, 차량 상황에 따른 진행 제한, 저장·이어하기·보상이다. 졸음 예방 효과나 안전성을 입증한 앱으로 표현하지 않는다. 향후 졸음 완화 가능성을 검증하려면 별도의 평가를 설계한다.

## 2. 제출 버전 범위
다음 우선순위는 11월 4일까지 세 앱을 제출하기 위한 개발 제안이다. 게임 삭제 결정이 아니다.

| 우선순위 | 기능 | 완료 조건 |
|---|---|---|
| P0 | 끝말잇기 | 시작→교대→오인식/오답 처리→종료→저장 |
| P0 | 초성 대결 | 하나의 초성에 맞춰 교대로 답하고 중복 금지 |
| P0 | 공통 음성 명령 | 선택·난이도·설명·일시정지·재개·그만 처리 |
| P0 | 주차/주행 규칙 구분 | 모의 차량 상태에서 타이머·제한 변화 확인 |
| P0 | 기록·포인트·모의 교환 | 중복 지급 방지, 주차 화면에서 조회·교환 |
| P1 | 스무고개 | 사용자가 질문, AI가 정답 목록에 근거해 답변 |
| P1 | 양세찬 게임 | 인물 정답 묶음과 스무고개 공통 엔진 사용 |
| P1 | 실제 외부 AI·사전 검색 | 모르는 표현·질문·단어 검증 보조 |
| 후속 | 정체 구간 대결·랭킹·실제 쿠폰·계정 | 서버·정책·제휴 검토 후 별도 구현 |

P1 메뉴를 보여줄 경우 '준비 중'으로 명시한다. '게임 4개 구현 완료'는 실제 네 게임이 작동할 때만 사용한다. 주행 중 사용 승인 전에는 주차 상태 시연을 기본으로 한다.

## 3. 게임 규칙과 미확정 값
### 3.1 끝말잇기
합의 반영:
- 매 판 AI가 먼저 시작한다.
- 사용한 단어는 사람·AI 모두 재사용할 수 없다.
- 한방 단어는 허용한다. AI는 가능한 한 한방 단어를 피한다.
- 틀린 단어는 이유를 알려주고 다시 말하게 한다. 오답 자체로 즉시 패배시키지 않는다.
- 음성 인식 오류는 계속 재확인할 수 있다. 인식 오류와 지식 오답을 구분한다.
- 주차 모드 기본 답변 시간은 AI가 말하기를 끝낸 뒤 15초다(실기 시험 뒤 10초에서 늘림).
- 오답 후 재시도에는 5초 추가라는 의견을 반영하되, 아래 타이머 상세 동작은 구현 제안으로 관리한다.
- '그만하자'는 '게임을 무효 처리하고 종료합니다' 안내 후 종료하며 보상은 없다.
- 난이도를 바꾸면 진행 중인 판을 무효 처리하고 새 난이도로 재시작한다.
- 뜻을 요청하면 짧게 설명한다.

구현 제안:
- 로컬 단어 목록에서 품사·표기·시작/끝 음절·뜻을 읽는다. 허용 품사와 두음법칙의 정확한 범위는 docs/DECISIONS.md에 확정값으로 기록한다.
- AI는 난이도별 후보 목록·선택 전략으로 답한다. 전체 사전을 무한 탐색하게 해 사실상 지지 않는 상대를 만들지 않는다.
- AI가 응답을 못 하는 판정은 제한된 후보 집합과 검증된 규칙에 따른다. 승률 수치는 플레이 테스트 후 조절한다.
- 잘못 들은 단어의 재확인 동안 판정·타이머를 멈춘다. 확인된 답만 중복 단어 목록에 추가한다.
- 주차 타임아웃은 즉시 패배시키기 전에 남은 힌트/연장 정책을 확인한다. 시간 종료와 사용자 발화 시작의 경합은 발화 시작 시각을 기준으로 처리한다.

미확정 사항을 임의로 합의로 만들지 않기:
| 항목 | 현재 확인한 의도 | 개발 시작 기본안 — 변경 가능 |
|---|---|---|
| 주행 시간 제한 | 없음 | 기다리는 동안 자동 패배 없음 |
| 주차 오답 +5초 | 추가 기회 | 남은 시간에 5초 추가, 안내 TTS 시간 제외 |
| 시간 초과 후 힌트 | 난이도별 차등 | 쉬움 2회·보통 1회·어려움 0회는 초기 제안값; 게임별 난이도 구성과 함께 확정 |
| 연장 길이 | 10초 연장 의견 존재 | 힌트 후 15초 새 창; 기본 타이머와 별도 설정 |
| 뜻 설명 | 요청 시 제공 | 횟수 제한 없음, 간결한 설명 |
| 두음법칙·허용 명사 | 허용 확대 의도 | 적용 목록·예외를 데이터 파일로 분리 |
| AI 패배 확률 | 테스트로 조절 | 실제 플레이 후 결정, 임의 수치를 확정사항으로 쓰지 않음 |

타이머와 힌트 정책은 RuleConfig로 모아 문서와 코드의 값이 달라지지 않게 한다. 앞선 대화에서 '보통 제거'와 '3단계'가 섞여 있으므로 전체 게임에 하나의 난이도 구성을 강제하지 않는다.

### 3.2 초성 대결
- AI와 사용자가 같은 초성 조건에 맞는 단어를 번갈아 말한다.
- 단어 중복 금지, 오인식 재확인, 오답 이유 설명, 종료·보상·일시정지는 끝말잇기 공통 엔진을 사용한다.
- AI 난이도는 3단계라는 합의를 반영한다. 단계별 어휘 폭·선택 전략은 설정으로 분리한다.
- 주행 중 무응답으로 패배시키지 않는다. 주차 중 시간 규칙은 공통 설정을 사용한다.
- 초성 길이와 주제 제한은 개발 기본안으로 2음절 일반 명사부터 시작한다. 영화·드라마 제목까지 무작정 허용하지 않는다.
- 후보가 부족한 초성은 시작 전에 제외한다. 시작하고 나서 정답이 없는 문제를 만들지 않는다.

### 3.3 스무고개 — P1 상세 설계
- AI가 정답 목록에서 하나를 고르고, 사용자가 질문한다. AI가 질문하는 아키네이터식 모드와 구분한다.
- 동물·음식·영화·드라마·스포츠 등 카테고리를 데이터로 관리한다. 선수 등 인물은 양세찬 게임으로 분리한다.
- 정답 추측도 질문 1회로 센다. 설명 재생·오인식 정정은 새 질문으로 세지 않는다.
- '네 / 아니요 / 애매해요' 또는 짧은 문장으로 답한다.
- 정답 획득까지 1~5회, 6~10회, 11~15회, 16~20회 구간으로 포인트를 다르게 설정한다. 정확한 포인트 수치는 아직 확정하지 않는다.
- 20회 뒤에는 안내하고 계속할지 묻는다. 계속하면 연습으로 진행하며 포인트는 지급하지 않는다.
- 난이도 쉬움/어려움, 어려움의 소폭 추가 보상은 이 게임의 기본안으로 관리한다.
- 정답 데이터: id, category, name, aliases, attributes, explanation, contentVersion.
- 사실 속성이 없는 질문에 AI가 임의 사실을 만들지 않게 한다. 판단 불가 응답과 재질문 절차를 둔다.
- 정답 목록은 버전이 있는 JSON으로 시작하고 검증 후 업데이트한다. 진행 중 판에는 시작 시점 목록 버전을 고정한다.

### 3.4 양세찬 게임 — P1 상세 설계
인물 정답 묶음을 사용해 스무고개 엔진과 질문 횟수·판정·저장을 공유한다. 이번 설계의 기본안은 '사용자가 질문해 숨겨진 인물을 맞히기'다. 정확한 역할 배치는 사용자 확정 전 변경 가능한 결정으로 남긴다. 인물 데이터는 공개적으로 검증할 수 있는 직업·작품 등으로 구성하고 사진·초상권 자료는 불필요하게 수집하지 않는다.

## 4. 음성 명령 설계
자주 쓰는 명령은 규칙으로 처리하고, 낯선 표현만 선택적으로 AI가 분류한다.

| 입력 예 | 의도 | 처리 |
|---|---|---|
| 그만, 그만해, 그만하자 | END_ROUND | 무효·무보상 안내 후 종료 |
| 잠깐, 멈춰 | PAUSE 또는 모호함 | 명확하면 일시정지, 애매하면 재확인 |
| 계속하자 | RESUME | 중단한 판 재개 |
| 쉽게 해줘, 어렵게 해줘 | CHANGE_DIFFICULTY | 현재 판 무효 후 재시작 안내 |
| 뜻이 뭐야 | EXPLAIN_WORD | 마지막 확정 단어 뜻 설명 |
| 잘못 들었어 | CORRECT_TRANSCRIPT | 이전 인식 재확인, 오답·중복 처리 취소 |
| 빨리 말해줘, 천천히 | CHANGE_SPEECH_RATE | 지원 TTS에서만 변경, 마지막 값 저장 |
| stop, 그만하랑께 | 명령 후보 | 별칭 또는 AI 분류, 불분명하면 확인 |

AI 분류 결과는 intent, slots, needsConfirmation 같은 제한된 구조로 받는다. 예시 단어를 설명하는 중의 '그만' 등을 실제 종료 명령으로 잘못 처리하지 않도록 입력 문맥을 구분한다.

예/아니요로 되묻는 질문은 두지 않는다(실기 시험 뒤 결정). 규칙은 요청할 때 안내하고, 시간이 다 되면 힌트를 바로 주며, '그만'은 바로 끝낸다. 판이 끝나면 다음 게임을 말로 고르고 난이도는 자동 변경하지 않는다.

모든 결과 안내는 짧게 한다. 포인트·쿠폰 상세 조회와 교환은 주차 화면에서 한다. 실제 주유·충전 쿠폰 발급은 P0 범위 밖이며 '데모 쿠폰 — 사용 불가'로 표시한다.

### SDK 경계
사용자가 확인한 문서 기준 Pleos STT는 결과 후보 1개이므로 N-best 후보 선택을 필수 전제로 만들지 않는다. 다시 묻기와 텍스트 정규화를 사용한다. TTS 속도 변경 API는 실제 문서에서 확인 후 사용한다. 미지원이면 Android TTS 어댑터의 동작을 검증하거나 기능 미지원으로 안내한다.

말하기 속도는 3단계·퍼센트 조절·마지막 값 유지가 가능한 설정 구조로 만든다. 어느 설정을 퍼센트로 조절할지는 대화 맥락상 명확하지 않으므로, 발화 속도 80/100/120%는 개발 제안값이다. AI 난이도 확률과 같은 설정으로 혼용하지 않는다.

## 5. 상태 모델과 저장
~~~mermaid
stateDiagram-v2
    [*] --> Setup
    Setup --> AiSpeaking: 게임·난이도 선택
    AiSpeaking --> Listening: TTS 완료
    Listening --> Confirming: 오인식·모호함
    Confirming --> Listening: 재입력
    Listening --> Judging: 확정 답변
    Judging --> AiSpeaking: 유효한 답변
    Judging --> Listening: 오답 설명 후 재시도
    Judging --> Result: 승패 확정
    Listening --> Paused: 일시정지·오디오 중단
    Paused --> Listening: 재개
    Listening --> Voided: 종료·난이도 변경
    Result --> Setup
    Voided --> Setup
~~~
도식 밖의 모든 진행 상태에서도 일시정지·종료 요청을 처리해야 한다. 종료 전에 들어온 늦은 STT/TTS 콜백은 sessionId/turnId로 무시한다.

저장 엔터티:
- GameSession: id, gameType, difficulty, roundMode, status, currentTurn, scoreEligible, contentVersion.
- Turn: id, sessionId, speaker, normalizedAnswer, acceptedAt. 음성 원본은 기본 미저장.
- RuleConfig: 게임별 시간·힌트·보상·AI 전략.
- RewardLedger: transactionId, sessionId, reason, points. sessionId+reason 중복 금지.
- UserSettings: 규칙 안내 여부, 발화 속도, 로컬 확인 별칭.
- SessionSnapshot: 사용 단어, 질문 횟수, 남은 타이머, 마지막 안전한 상태.

강제 종료 후에는 '일시정지된 판'으로 복원하고 사용자의 재개를 기다린다. OS 강제 중지 동안 음성 인식이나 게임이 계속 동작하는 것으로 만들지 않는다.

사용자 선택 규칙은 한 판 동안 고정한다. 단, 주차 중 시작했다가 움직이는 경우 플랫폼의 제한은 즉시 적용한다. 개발 제안: 타이머 중지·필요 시 게임 일시정지 후 다음 판에서 모드를 변경한다. 주차 모드라는 이유로 실제 주행 중 제한시간을 유지하지 않는다.

## 6. 화면과 모의 입력
1. 게임 선택: 구현된 게임과 준비 중 게임 구분.
2. 난이도·규칙 안내: 음성 중심, 주차 중 큰 선택 버튼.
3. 진행: 마지막 발화, 현재 차례, 주차 타이머, 마이크 상태.
4. 결과: 승리/패배/무효, 지급 포인트.
5. 주차 보관함: 기록, 포인트, 모의 주유·충전 교환.
6. 시연 패널: 모의 주차/주행/오디오 중단, 텍스트 입력. 정상 사용자 흐름과 분리.

실제 음성 API가 준비되지 않은 텍스트 주입 시연은 '음성 입력 대체 시연'으로 표시한다. 이를 실시간 음성 인식 성공으로 설명하지 않는다.

## 7. Claude Code 작업 묶음
- G01: 독립 실행 앱과 포트, 모의 차량 상태, 데이터 저장.
- G02: 끝말잇기 순수 엔진과 소규모 검수 단어 데이터.

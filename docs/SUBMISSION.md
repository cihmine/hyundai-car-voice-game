# 1차 제출·가산점 준비 체크리스트
확인일: 2026-10-31 · 내부 목표: 2026-11-04

## 공식 안내로 확인한 범위
- 공식 마감: 2026-11-15. 정확한 마감 시각과 공지 변경은 제출 전 공식 페이지에서 다시 확인한다.
- 필수: 공식 접수양식에 기획 내용 작성, 참가자 전원의 개인정보 동의·서명·날짜.
- 선택 가산점 대상: 프로토타입 시연 영상, GitHub 저장소의 소스 코드와 APK. 개발 산출물 수준에 따른 단계별 가산점이며 정확한 점수는 확인된 안내에 공개돼 있지 않다.
- 시연 영상에는 목업·프로토타입·화면 녹화가 인정된다.
- 숏폼은 별도 특별상이며 본상 가산점 대상이 아니다.
- 2차 PT 대상자는 PT 전에 실제 동작 가능한 앱을 완성해야 한다.

## 앱별 제출 묶음
복수 출품을 전제로 각 작품을 따로 식별할 수 있도록 준비한다. 작품별 공식 양식과 링크를 분리해 관리하는 것을 권장하며, 복수 작품을 메일 한 통/여러 통으로 제출하는 정확한 방식은 주최 측 안내를 최종 확인한다.

| 항목 | 1번 말게임 | 2번 주차 충격 확인 | 3번 낮잠 알람 |
|---|---|---|---|
| 작품명·버전 | 미정 | 미정 | 미정 |
| 공식 기획서·동의서 | 준비 필요 | 준비 필요 | 준비 필요 |
| GitHub URL | 생성 후 기입 | 생성 후 기입 | 생성 후 기입 |
| 소스 커밋 | 빌드 후 기입 | 빌드 후 기입 | 빌드 후 기입 |
| APK 경로 또는 Release URL | 빌드 후 기입 | 빌드 후 기입 | 빌드 후 기입 |
| 시연 영상 URL/파일 | 촬영 후 기입 | 촬영 후 기입 | 촬영 후 기입 |
| 실제/모의 범위 | 구현 후 확인 | 구현 후 확인 | 구현 후 확인 |
| 최종 설치·접근 확인 | 미실행 | 미실행 | 미실행 |

GitHub 저장소에는 소스와 실행 가능한 release APK를 함께 준비한다. 기본 APK 위치는 apk/이고 파일명은 '팀명_앱이름_release.apk'이다. 용량이 GitHub 업로드 제한을 넘으면 GitHub Releases에 등록한 주소를 제출한다. 비공개 저장소도 가능하며, 공식 안내의 심사용 계정을 Collaborator로 초대하고 마감 전 접근을 확인한다. 계정 이름을 추정해서 초대하지 않는다.

README 필수 정보: 앱 이름·한 줄 소개, 실행 방법, 테스트 환경·필요한 설정, APK 위치 또는 Release 링크. 여기에 실제 구현/모의 기능/미구현 기능과 시연 순서를 추가하는 것을 권장한다.

## 우리 자체 품질 확인
- [ ] 앱마다 서명된 release APK를 새로 설치해 실행했다.
- [ ] APK의 기능이 시연 영상·README 설명과 일치한다.
- [ ] 영상과 README에 차량 데이터·제어 시뮬레이션 범위를 표시했다.
- [ ] 영상 링크를 심사자가 열 수 있다. 로그인·권한 오류가 없다.
- [ ] README의 빌드 명령을 실제로 확인했다.
- [ ] 비밀키·서명키·동의서·개인정보가 Git 및 이전 커밋에 없다.
- [ ] 단어 데이터·음원·폰트·라이브러리 등의 이용 조건을 확인했다.
- [ ] 미검증 실차 기능을 작동한다고 표현하지 않았다.
- [ ] 앱별 영상은 핵심 문제→사용→결과가 보인다. 1~2분은 자체 권장 길이이며 공식 제한으로 표현하지 않는다.
- [ ] 주유·충전 쿠폰은 실제 제휴 없이 사용 가능한 것으로 표시하지 않는다.

## 접수
접수처: appdevchallenge@hyundai-partners.com
공식 제목 형식: [차량용 앱 개발 공모전] 팀명(개인은 성명)_대표자명

대표자는 팀원 전원을 CC한다. 수정 제출은 마감 전에 전체 제출 자료와 서명한 동의서를 다시 제출하고, 제목에 '[수정제출]'을 붙인다. 마지막으로 제출한 자료가 최종본이므로 앱별 파일명·버전을 명확히 관리한다.

이번 개발 패키지는 공식 접수양식을 대신하지 않는다. 계획만 제출할 때와 코드·APK·영상을 함께 제출할 때의 개발 산출물 수준은 다르며, 가산점 획득을 보장하지 않는다.
